# 独立网页登录与播放验证

`web_playback.py` 使用当前应用已实现的网页登录二维码协议进行独立测试。它不读取或修改模拟器的账号、曲库、队列及设置；Cookie、扫码票据和下载地址只保留在进程内存，不写入结果文件。

需要 Python 3、Pillow 与 qrcode。启动参数为新输出目录、用户指定的文件搜索关键词、目标文件的准确字节数：

```text
python web_playback.py --output <新的私有输出目录> --keyword <音乐关键词> --size <文件字节数>
```

显示输出目录中的 `login-qr.png` 让用户用夸克扫码确认，脚本最多等待 5 分钟。登录后只搜索目标文件；仅有一个名称与大小匹配的 FLAC 候选时才继续，否则退出并要求明确选择。

依次验证 OpenList Cookie 视频播放接口、PC 下载接口的普通浏览器与 PC 客户端请求头。获取到媒体地址时最多读取 64 KiB，记录状态、字节数及 FLAC/HLS 文件头，不输出媒体地址或完整响应。文件头与 Range 成功不等同于完整解码、拖动或整首播放通过。全部操作为登录和读取，不转存、分享、上传、重命名或删除网盘文件。

`result.json` 只包含脱敏后的阶段和结果。结束或失败后清理内存 Cookie 和二维码文件；重新运行必须使用新输出目录。不要把包含用户真实关键词的命令、二维码或原始会话资料提交到仓库。
