# 提交与脱敏

## 文档维护

- README 帮助读者了解功能、完成配置并找到入口；架构和功能文档描述当前实现、原因与使用方法。行为变化时直接修正文档，不在文末不断追加“后续进展”。
- 发布说明与更新日志只记录版本改动，遵循 [发布说明写作规则](releases.md#发布说明写作规则)。测试指南维护可重复执行的步骤、环境要求和判定标准，不累计每次运行的数量、摘要和安装流水账。
- 提交文档前明确读者和维护用途：安装配置、当前架构与设计原因、接口协议、可复现的测试或排障步骤。只有无法由现有文档清楚表达、仍约束当前实现的决策，才单独成文并写明适用范围与依据。
- 不提交或保留独立 review 文档。已修复问题清单、逐轮调查、反编译过程、个人调试经验和执行结果不作为项目文档提交，也不改名另存为阶段报告。有效结论按主题合入现有说明，复现条件进入回归测试；原始报告和日志留在本机忽略目录，审查讨论与修复经过由 PR／Issue 和 Git 记录承载。
- 同一事实维护一个主要出处，其他文档链接引用。协议来源与关键设计取舍可以保留必要证据；跨项目建议、过期方案、设备恢复过程不混入维护指南。删除或合并文档时同步修正链接。

## 提交检查

版本库只保留代码、空配置模板、合成测试数据、图标源资源和脱敏研发文档。`.gitignore` 排除本机 SDK／IDE／构建目录、客户端配置、签名材料、授权实验结果、数据库和原始调试证据。

提交前检查暂存区，而不是只检查工作目录：

```sh
python3 tools/check-publish.py
```

本机存在客户端配置时，可加一次签名密钥和连接凭证的精确值检查。脚本仅报告文件名和规则名，不打印实际匹配内容；公共 clientId 标识不是用户凭证，原有拒绝不适用客户端的校验字符串保留：

```sh
python3 tools/check-publish.py \
  --private-config android-app/app/src/main/assets/quark_cli_client.json
```

脚本是针对本仓库的辅助检查，不替代人工审阅。新增文档需确认没有个人绝对路径、真实账号与目录、授权页面参数、二维码、Cookie、令牌或签名下载链接。新截图需要使用无账号的演示环境和合成素材；现有原始联调截图不进入仓库。

APK 在构建时可能包含本地客户端配置，因此不会随源码提交。受控的标签发布流程会单独发布已签名 APK；配置分发边界与 Secrets 要求见 [发布说明](releases.md)。不要先提交敏感文件再删除；删除不能清除已创建的 Git 历史。第三方许可原文保留，不能因脱敏而删除版权归属。
