# 夸克接入

## 当前路线

从 0.5.7 起，默认使用网页扫码登录。添加音乐目录的夸克入口优先复用已保存的网页登录状态；没有网页账号时打开网页二维码，不因存在 Token 账号而改走 Token 登录。网页登录采用已验证的 PC 文件取址方式，音乐仍由 Media3 按需读取、边播边缓存。

账号管理将网页扫码放在主要入口，Token 授权及其目录放在“其他登录方式”。更改默认入口不迁移已有来源或播放队列；Token 目录继续使用原授权，用户从网页目录点歌后才建立对应播放队列。

网页二维码与会话协议参考 [QuarkPan](https://github.com/lich0821/QuarkPan)。可选 Token 路线参考 [quarkclouddrive](https://github.com/quark-clouddrive/quarkclouddrive_offical) CLI 1.0.18 的 Agent 授权协议，由 Android 完成授权页、二维码、轮询、兑换及读取。车机不运行 Node.js 或 Python，不包含 CLI 自动更新、会话追踪或文件上传／删除功能。协议可能变化；实验流程成功不等于平台为本项目分配了独立应用身份。

## Token 路线的本地客户端配置

复制 `android-app/config/quark_cli_client.example.json` 到 `android-app/app/src/main/assets/quark_cli_client.json`，填写适用于该使用场景的 `clientId` 和 `signKey`。真实文件不纳入 Git，仓库不会代替构建者取得客户端配置。

缺少或留空配置时，应用仍可构建；直接授权会提示安装包未配置。不要把用户授权码、访问令牌、刷新令牌或 Cookie 填进该客户端配置。

客户端签名参数进入 APK 后可被提取，不能视为设备端不可读取的秘密。部署需要后端保管的长期应用密钥时，应采用独立获准的服务端方案，不能将本实验协议适配视为同一资质。

## Token 会话保存与目录访问

用户令牌通过 Android Keystore 加密保存；切换或重新选择来源时复用账号。访问令牌失效或临近到期时刷新，同账号并发请求合并；访问和刷新令牌一致保存，旧响应不能覆盖新会话。

授权页面验证 HTTPS、预期主机和路径，以及页面码绑定；兑换时核对设备绑定。二维码可刷新，授权码输入只作为备用。只访问用户实际授权的目录；手机页面上的长期授权截止日期不是访问令牌寿命。

目录按服务端游标翻页，检测循环并保留完整 FID；下载地址临时解析。读取所需请求头仅发送至对应来源，日志不输出带凭证的地址或令牌。

## 验证与限制

已有隔离验证版完成新授权、目录扫描、首次播放、主动刷新、刷新后直接网络 Range 读取和进程恢复。到期后的并发刷新与旧响应保护由本机测试覆盖；未等待长期授权自然到期，也未完成所有实车验收。详见 [测试说明](../android-app/TESTING.md)。

`open-service/` 是早期专用连接服务原型，目前没有对应的应用配置入口，不属于当前直接扫码所需部署组件。它保留为研发参考，准入、回调和刷新路由必须独立验证。

## 网页登录失效后的恢复

旧网页登录目录（QUARK）和扫码开放授权目录（QUARK_OPEN）分别绑定自己的账号。建立新的开放授权不会自动迁移已有网页登录目录，也不会改变播放队列。

网页登录收到 HTTP 401/403 时，播放页显示重新连接操作，保留歌曲、位置和队列。重新连接使用当前目录的原凭证槽位；先在内存中验证新会话、原目录，以及每个非空来源的一首已有文件的下载地址，再加密提交新凭证。验证失败或提交前取消时保留旧凭证。若所验证的旧文件已删除或当前账号无法读取，需要检查原目录或通过来源页重新选择目录，不能把校验失败当作成功登录。

从播放错误入口重新登录成功后，只在当前曲目未改变时重试原队列。普通账号管理重连不自动开始播放。网络超时、断连及可重试服务错误仍按既有策略持续重试；登录失效需要重新授权，不作为普通断网无限请求。

## 当前授权接口的单文件下载限制

实际 Token 请求曾返回 HTTP 400、`errno=23018`，`error_info=download file size limit[52428800]`，即该请求受到 50 MiB 的单文件下载限制。这是服务端拒绝，不是连接中断或 Token 失效；没有证据能将原因进一步归结为某项会员权益或客户端资格。

从 0.5.5 起，播放器识别这一响应并显示服务端给出的文件大小上限，不自动刷新 Token 或无限重试，也不会切换到网页 Cookie。未知格式只显示安全的通用下载权限提示，不直接展示服务端原始信息。超限文件的实际播放仍依赖网盘端允许下载，应用文案修复不代表解除了该限制。

## QuarkPanTool 文件大小限制方案对照

核对 [QuarkPanTool 固定版本源码](https://github.com/ihmily/QuarkPanTool/blob/0ecfbb0152da0d3364bbee32cbf30a1b0ab31b4a/quark.py#L339-L377)：使用网页 Cookie 请求 `drive-pc.quark.cn/1/clouddrive/file/download`；遇到业务码 23018，将 User-Agent 从普通浏览器改为 `quark-cloud-drive/2.5.56` 的 PC 客户端标识后再请求一次。这是 Cookie 接口上的兼容方式，不是分割文件或修改 HTTP Range。项目 README 声称能避开 web 端大小限制。首次只做了 Token 对照，后续已补充独立网页登录实测，见下节。

在 BlueStacks 的 0.5.5 Token 测试实例中，以同一已授权文件（54,123,966 字节）在内存中对照替换该 User-Agent，仍调用原 Token 接口，返回 HTTP 400、errno 23018、`download file size limit[52428800]`，未读取到音频。由此可确认仅移植该 PC User-Agent 无法解决本次 Token 接口限制；不据此宣称所有其他接入方式都无效。播放器代码和凭证未切回 Cookie，临时诊断组件已卸载。

## 在线播放与下载接口的边界

播放器目前是按需读取、边播边缓存，并不等待整首下载完成；但它使用下载地址 API 获取音频地址。因此本次 50 MiB 错误只验证了该下载路径的限制，不能外推为夸克自身的在线播放也受同样限制。

[OpenList 的夸克驱动](https://github.com/OpenListTeam/OpenList/blob/main/drivers/quark_uc/util.go#L139-L168) 展示了独立的 `/file/v2/play/project` 视频转码播放接口，公共请求方法携带 Cookie。该实现不能作为 FLAC 音频或当前开放授权 Token 可用的证明。另一个[第三方音频播放脚本](https://greasyfork.org/en/scripts/556478-%E5%A4%B8%E5%85%8B%E7%BD%91%E7%9B%98%E6%92%AD%E6%94%BE%E9%9F%B3%E9%A2%91/code) 实际调用 `fetchDownloadFileInfo`，然后将 `download_url` 赋给音频元素，也不能据此认定存在独立音频流 API。尚未确认可供当前 Token 使用的 FLAC 播放接口。

完整 OpenList 三种驱动的对照及当前 Token 请求实测结果，见 [OpenList 夸克播放路径调研](openlist-quark-playback-review.md)。

## 网页登录补测与 0.5.6 接入

用户在独立 Python 会话扫码网页登录后，对名称及字节数唯一匹配的 FLAC（54,123,966 字节）作只读测试：

| 路径 | 响应 | 结果 |
| --- | --- | --- |
| Cookie 视频播放 `/file/v2/play/project` | HTTP 400、code 14018 | 本次没有返回媒体地址；不能由此证明所有 FLAC 或其他官方端都不支持播放 |
| Cookie PC 下载接口＋普通浏览器 UA | HTTP 400、code 23018 | 仍触发文件大小限制 |
| Cookie PC 下载接口＋夸克 PC 客户端 UA | 地址 HTTP 200、code 0；媒体 HTTP 206 | 成功读取 65,536 字节，具有 FLAC 文件头，类型为 audio/x-flac |

因此选择已验证的 Cookie PC 文件地址＋按需 Range 读取路径接入，不把失败的视频接口当作已实现的音频播放接口。0.5.6 的网页登录提供方改用 `drive-pc.quark.cn`，获取文件地址时使用已验证的 PC UA 及 sys/ve 参数，并将当前 Cookie、Referer、同一 UA 传递给原有 Media3 缓存数据源。无需先完整下载歌曲，也不转码或主动更换格式。

Token 提供方不受这次改动影响，不会静默跨账号或切换认证。原 Token 来源仍受到此前测得的大小限制，只有网页登录来源使用新的读取方式。独立实验的 Cookie、票据、媒体 URL 均仅存于进程内存，实验结束已清理，没有导入模拟器。

本次真实验证范围为获取地址和 FLAC 首段读取；尚未在修复 APK 的网页登录来源上验证整首解码、跳转或完整离线。测试脚本见 `tools/quark-auth-lab/web_playback.py`。

## 0.5.8：来源登记阶段防重复

同一音乐目录只有一份来源记录和一份曲库。登录方式是访问入口，不在扫描后按歌曲名称做展示层去重。

- 来源登记由串行互斥锁保护。已经登记的登录账号及目录标识再次出现时，返回已有来源，不新增曲库、不启动扫描。
- 使用 `source_access` 将不同登录入口关联到同一 `source_id`，关联后再次添加直接复用。应用拿到的网页和 Token 标识不能直接互认，因此首次跨方式关联需要用户在扫描前确认是同一账号的同一目录。路径及目录名只用于提示候选，不用于自动认定账号相同。不同账号或不同目录可以明确选择独立添加。
- 目录选择器在读取目标目录前检查已有登记。已存在时优先提供使用现有曲库；主动继续浏览子目录才执行目录读取。首次建库复用选择器已取得的根目录列表，不重复请求；递归扫描仅补读子目录。
- 已有关联会继续使用原来源的读取方式，不会静默改变认证或把不同接口的文件标识混用。显式刷新、改变包含子目录范围，仍会更新原曲库。
- 历史重复来源不能靠名称自动删除。可在来源中移除某一目录，或在账号管理清除本机 Token 授权与对应目录；这些操作只删除本机记录和对应离线缓存，不删除网盘文件。Token 移除同时清理本机凭证和已登记的该账号入口。
- 移除会过滤播放队列，并与本机数据库写入顺序一致提交。当前歌曲被保留时保留位置；当前歌曲被移除时暂停。旧检查点不会恢复已移除来源。网盘端撤销授权与本机曲库清理是不同操作，仍需处理本机旧记录。

## 0.5.9 缓存完成状态

播放缓存的最后一个分片原本会在缓存写入关闭时提交。播放器可能已经读完指定范围，但仍在播放缓冲音频，尚未再次读取 EOF 或关闭数据源，因此完整状态的可见时间可能滞后。后续歌曲的预缓存任务会主动读完并关闭，时序不同。

播放用数据源现在在已知范围长度的全部字节成功写入后立即提交该范围的末片；未知长度仍在关闭时提交。完整性判断仍检查整首文件的连续覆盖，不把播放进度当成缓存进度，存在跳转造成的未读区间时仍显示部分。该修改不增加下载任务，也不调整后续三首预缓存数量。


## 0.5.25：网页登录的并发凭证保护

网页请求捕获发送时的 Cookie 及其加密记录修订值。接收响应时检查修订，在 CredentialVault 的同一监视器内完成比较、合并和提交；重新登录、普通轮换与断开账号不能被旧响应覆盖。保存相同明文也会生成新的加密记录，避免相同文本重新登录时失去代次保护。

迟到响应会改用当前会话重试；账号已断开时不恢复旧凭证。文件取址结果使用该响应接受的 Cookie，避免把旧会话取得的 URL 与另一个新登录的 Cookie 拼接。该机制保护本地并发一致性，不改变夸克服务端会话的有效期或权限。
