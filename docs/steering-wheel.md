# OneOS 方向盘按键适配

适用版本：0.5.27（包含 0.5.26 的方向盘实现）。适配目标：领克 01 / LYNK OS N；真实车辆权限和回调尚待验证。

## 使用方式

在「设置 → 方向盘按键」开启「启用 OneOS 车机适配」。默认关闭，原有 Android 标准媒体按键仍可直接控制媒体会话。

停车后可先开启「只检测按键，不控制播放」，逐个按方向盘播放、左、右键，查看连接状态、最后收到的键码、回调和识别结果。只有服务注册成功后，三类标准媒体按键才交由本适配层处理；检测模式下这三类事件不会改变播放状态。其他系统控制入口仍保留。

| 来源键码 | 默认含义 | 单击 | 双击 | 长按 |
| --- | --- | --- | --- | --- |
| 200085 | 播放键 | 播放 / 暂停 | 不执行 | 不执行 |
| 200088 | 左键 | 上一首 | 不执行 | 不执行 |
| 200087 | 右键 | 下一首 | 不执行 | 不执行 |

每项可以改为不执行、播放／暂停、下一首、上一首、播放、暂停。设置保存在本地；重新启动保留。恢复默认只重置动作，不改开关。

## 接口来源与兼容边界

参考来自对小八客户端及其携带 OneOS SDK 的本地分析，**不是公开官方 SDK 文档，也不是实车验证结果**。Cruise Tune 独立实现适配，不引入参考 APK、解密 DEX、SO 或其业务代码。

1. 显式绑定 `com.geely.service.oneosapi/com.geely.service.oneosapi.OneOSApiService`，只接受系统预装或更新的系统包。
2. 核验根 Binder descriptor 为 `com.geely.lib.oneosapi.IServiceManager`，只调用已从 SDK 确认的 `getService`（事务 2）。参考客户端给出了服务 ID 候选 8、12、16、20、24、28、32、36、40；这些只是有限的只读查询候选，**并未确认哪个是输入服务**。只接受 descriptor 恰为 `com.geely.lib.oneosapi.input.IInputManager` 的返回对象，不使用其他返回服务，不试探事务号。
3. 从车辆已安装的系统 OneOS／媒体中心 APK 加载接口类型。要求能验证 `registerKeyListener(IInputListener, String, int[])`、`unregisterKeyListener(String)` 和返回整数的 `getControlIndex()`。通过 SDK 的具名 Proxy 方法注册、注销和读取菜单，**没有采用参考客户端猜测的注册事务 3、查询事务 5，更没有尝试注入按键事务 3～8**。
4. 回调使用 `com.geely.lib.oneosapi.input.IInputListener`；方法参数及每个回调的事务编号从同一 SDK 核验、读取。只有 OneOS 服务 UID 或 Android system UID 的回调被接受，载荷长度、接口令牌均校验。
5. 注册成功显示「已连接，等待按键」，它只表示接口注册完成；必须收到实际回调才算验证输入路径。系统包缺失、权限不足、SDK 类型缺失或签名不匹配均明确显示原因，保持标准媒体键路径。

尚未确认的厂商版本不会退回猜测事务号。若实车显示接口不兼容，需要依据该车机的 OneOS 系统 SDK 补充对应契约，而不是改设备型号或授予无关权限。

## 识别与播放行为

- 用户实车反馈：方向盘通过菜单复用同一套按键，媒体菜单中才控制原厂 QQ 音乐。音频正在播放、应用处于前台或音频焦点正常，都不能单独证明当前按键属于媒体菜单。
- 样本 `SteeringWheelService` 将查询命名为 `getControlIndex`，按 2=媒体、3=电话、其他=非媒体判断；严格模式默认开启。但查询失败时可能通过电话状态推断、默认返回 2，而且短按与其他手势的检查位置不同。本实现不沿用这些放行路径。
- 收到有效回调时先读取菜单，只有值 2 才进入手势识别；手势触发动作前再次读取。监听期间每 500ms 更新菜单诊断，观察到菜单切换会取消待执行单击、双击／长按动作。无法读取、未知值和电话菜单全部不执行。单击的 350ms 等待不会缓存“允许执行”的结论；已观察到离开再回到媒体菜单也不恢复旧动作。
- 菜单数值语义来自样本，需实车比对媒体／电话／其他菜单。这里的菜单门控与“当前使用哪个播放器”是两件事；仍需确认原厂媒体中心是否同步处理相同按键，是否需要另行接入厂商媒体中心。当前实现不会主动抢走 QQ 音乐的系统控制权。
- 单调时钟计时，按键分别维护状态。单击等待 350ms；窗口内第二个有效短按取消单击，执行一次双击。小于 80ms 的重复短按不构成双击。
- 原始键事件不直接执行；原生 double 回调不作为第二条执行路径。当前识别依据两个 short 回调。若实车只发送原生 double 而不发送两个 short，需要根据实测增加另一种互斥输入模式。
- 长按开始／触发合并为一次长按，取消待执行单击；松手后 300ms 内的短按及迟到的 long 回调被抑制。暂不支持持续长按调音量。
- Binder 线程只转交事件。事件携带接收时间，主线程拥塞不改变双击间隔；超过 1 秒才处理的事件丢弃，避免延迟操作。
- 关闭适配、切换检测模式、修改映射、服务断连和熄屏均取消待处理手势。迟到的旧回调、排队中的旧播放命令由代次校验拒绝。
- 动作定向送进本应用的 `PlaybackService`，与其他内部命令串行执行，不枚举其他 App 的 MediaController，不使用全局媒体键注入。
- 播放／暂停基于 `playWhenReady`，缓冲时也能暂停；上一首／下一首复用现有队列及错误后重新准备逻辑，暂停时切歌保持暂停。完整缓存仍直接本地读取，不需刷新网盘目录。首曲按上一首回到开头；队尾下一首不强行重排或重新取曲库。
- 熄屏、AudioManager 非普通模式、播放器音频焦点受抑制、其他音乐正在使用输出而本播放器未请求播放时，不执行动作。该保护依赖系统暴露的音频状态，不能替代领克电话／语音焦点实测。
- 成功注册后，MediaSession 收到 85／87／88 的 `MEDIA_BUTTON` 回退事件会被消费，以免一个实体键既走 OneOS 又走系统键切两次。通知栏直接传输控制不受此分流影响；断连后恢复标准媒体键。启用适配期间，蓝牙设备发出的相同标准键也可能被消费，因此只在原车标准按键不工作时开启。

## 生命周期、重连与权限

监听依附播放服务，不依附设置窗口，退出设置后继续监听。播放服务销毁会注销监听、关闭回调、解绑服务；进程被系统回收后不会靠厂商私有手段自行唤醒，需重新打开播放器或由系统启动媒体服务。

暂时断连、绑定超时或远端异常按 4、8、16、30 秒退避持续重连，每次重新核验接口。权限不足或契约不匹配停止盲目重试，用户关闭再开启可以重新检测。注册后的输入 Binder 死亡也触发重连。远端调用在 IO 线程串行执行，不阻塞播放器主线程；Android 同步 Binder 调用本身不可被协程强行中断，取消时先关闭本地回调，调用返回后执行清理。

不新增 `READ_LOGS`、电话状态或通知监听权限，不自动授权、Root 或更改系统应用。参考客户端中的日志补充主要针对自定义／静音等特殊键，不是已验证的左右播放键备用输入源，因此本版本没有系统日志监听分支。

## 验证与实车验收

0.5.26 云端发布因缓存选择测试的瞬时就绪状态断言失败而停止，未公开 Release。后续复现表明 Robolectric 默认把所有已写入 PCM 帧视为已播放，8 秒的短音频在 1 秒测试推进中就自动跨到后续曲目。0.5.27 仅在 `CachedTrackSelectionTest` 内使用固定的模拟播放头，使选择、缓存路由、暂停意图与重新准备断言不受音频提前播完影响；新增回归在修正前于 API 28／33 均失败，修正后整组 28 项通过。真实解码、缓存读取和播放服务仍参与测试，应用运行逻辑未因此改变。

0.5.27 本地全量 339 项 Android 测试、release lint、签名构建通过。其 DEX 和原生库与已完成模拟器复验的 0.5.26 本地包逐项一致；APK 整体仍因版本及构建元数据而有不同摘要，发布成品另以 Release 中的校验文件为准。

2026-09-15：337 项 Android 自动化测试通过，release lint 与 APK 构建通过。新增 8 项 Android 9／13 下的组合回归，串联真实控制器、菜单查询、手势计时和持久化映射，验证菜单切换、双击去重、检测模式不执行、关闭后恢复标准媒体键。版本 0.5.26 / versionCode 35，APK SHA-256 为 `7a56bda485dbf107b94652dce962071ad45e418b0d0be7096677245d9e5a287f`，签名与 0.5.25 一致。

BlueStacks Android 13 / ARM64 已完成最终 APK 的覆盖安装复验；从设备读取的安装包与上述 SHA-256 一致。已有曲库和保存位置保留，启动保持暂停。设置页开启适配后明确显示缺少 OneOS 服务、菜单无法确认，没有误显示连接成功或自动播放；目标应用 AndroidRuntime 错误记录为 0。右键双击改为下一首、打开两个开关后重启，映射与开关均保留；随后恢复测试前的映射和两个关闭状态。960×540dp 横屏及 1.6 倍字体下的方向盘设置页可正常显示、滚动和操作。

360×640dp、1.6 倍字体的窄屏复验已补完：标题与开关文字可换行显示，映射列表可滚动并聚焦，动作选择框的全部选项（含末尾暂停）可以访问，保留原映射并返回设置页成功，列表底部与完成按钮可访问。没有发现内容永久遮挡或操作不可达。

共享模拟器使用结束后，已恢复本任务最初的显示配置并通过只读探针核对：1920×1080px、density 320、无 size/density override、font_scale 1.0、user_rotation 0、accelerometer_rotation 0。播放器保持暂停，已有曲库和保存位置仍在；ADB 按用户要求保持开启。窄屏补测没有修改应用代码或更换 APK，沿用已通过的 337 项自动化测试结果。

以上为模拟器界面和合成接口测试，不据此宣称真实方向盘、真实菜单或原厂 QQ 音乐共存已验证。

自动化涵盖：350ms 单双击边界、80ms 去重、长按合并及松手抑制、不同键独立、主线程延迟、取消后无残留动作；合成 Binder 只读服务发现、严格 descriptor、具名 SDK 注册／注销、拒绝错误 UID 与截断载荷；无服务、权限拒绝、非系统伪装、断连重连及旧回调失效；完整缓存切歌、暂停保持、播放重建、熄屏／通话门控；映射保存及设置页触摸控件。

合成 SDK 故意使用不同于参考 APK 的事务号（包括菜单查询），以确认实现读取 SDK 契约，未硬编码猜测值。额外验证菜单 2→3／未知、读取失败、350ms 期间切菜单、离开再返回媒体菜单、旧响应覆盖以及连接重置场景。测试替身不能证明领克 SDK 的方法签名与其一致。

实车待确认：

1. 能否绑定 OneOS，以及是否允许当前应用签名注册监听。
2. 输入服务 ID、SDK 方法签名、回调 UID，播放／左右键实际码值及二级参数含义；实际媒体菜单是否对应 `getControlIndex() == 2`。
3. 短按、快速双击、长按松手是否符合当前回调组合，有无另一个 OEM 控制路径同时执行。
4. 导航播报、通话、语音助手、其他音乐应用、ACC 休眠唤醒的音频焦点和服务重连行为。
5. 断网或授权报错后切到完整缓存的真实播放、熄屏保持暂停，以及亮屏后的手动恢复。

需要反馈时提供「方向盘按键」页截图和按键操作顺序即可；不需要 VIN、账号凭证或全量系统日志。
