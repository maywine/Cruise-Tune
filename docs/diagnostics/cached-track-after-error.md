# 网盘报错后完整缓存歌曲无法切换播放

日期：2026-09-15。定位基于 0.5.23（f4c7055）。

## 现象与原因

用户报告：夸克报错后，连续手动切换几首显示“已缓存完整”的歌曲均不能播放；刷新目录后，再从曲库点歌曲才能恢复。

代码及合成回归复现了一个相符的缺陷：终止错误令 Media3 进入 STATE_IDLE，而主界面的上一首／下一首仅调用 seek。seek 会更新当前索引和歌曲信息，但不会重新 prepare，因此缓存标签能够更新，实际数据读取却没有重新开始。旧错误及 needsLogin 提示也可能继续留在会话中。

曲库点歌则会设置队列并执行 prepare/play，所以能重新启动。管理页的目录刷新调用扫描和曲库更新，并不直接启动播放器；扫描也可能更新网页会话或文件元数据，但对本次完整缓存的复现而言，恢复依靠的是重新准备播放，不需要刷新网盘目录。

## 缓存与重试边界

- 正常播放优先读取离线缓存，再读取流式缓存，缺少字节时才经过网盘取址与网络数据源。完整缓存歌曲不需要先验证网盘登录。
- 临时网络失败继续按 2、4、8、15、30 秒间隔退避，后续维持 30 秒，不设次数截止。
- 登录失效、权限和明确文件错误不能都当作普通断网无限请求；当前缺陷发生在读取已终止后，用户再次切歌未重新 prepare。
- 一首歌的错误不能阻止其他完整缓存歌曲被读取。后台预读或后 3 首预缓存仍可能请求别的未缓存歌曲，验证时应按曲目区分。

## 0.5.24 修复

播放服务记录终止错误／播放意图下的手动跳转，在该轮位置和切歌回调完成后，为仍处于 IDLE 的选中项重新 prepare，并同步会话状态。该处理覆盖来自界面和媒体控制的跳转，不依赖每个按钮单独调用重试。

保留 playWhenReady，原本暂停时不会自动播放；熄屏时不重新准备。刚恢复但尚未开始的队列，仅浏览下一首不会主动启动加载。正常 READY/BUFFERING 切歌路径保持原行为。

## 复现与检查

CachedTrackSelectionTest 使用真实 Media3 1.11.0 播放器、合成 WAV、缓存文件及必定失败的网络上游：

1. 第一首未缓存，返回模拟夸克终止错误。
2. 后三首分别写入完整流式缓存／离线缓存，核对显示完整。
3. 使用与下一首按钮相同的播放器跳转命令，核对选中项进入 READY、播放意图、会话错误清除，以及缓存歌曲的上游请求次数为零。

修复前原始 8 个实例有 6 个失败，两个“直接 prepare 完整缓存”的对照实例通过；修复后原始 8 个实例通过。扩展回归包含上一首、快速连点、暂停、熄屏及未开始队列，覆盖 API 28／33。

恢复取消测试拆为独立实例，避免前一实例的显式切歌正常启动下一首后污染后一实例计数。只在合成测试数据中操作缓存；没有读取或改动车机账号、数据库或音乐文件。缺少最初那次夸克响应的现场日志，不能据此确定其 HTTP 状态或上游拒绝原因；本次确认并修复的是后续完整缓存歌曲无法通过切歌重新开始的问题。
