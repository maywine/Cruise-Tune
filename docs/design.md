# 界面与图标

## 触摸布局

横屏优先，大尺寸主操作固定在底部。进度、时间、队列／曲库标签和上一首／播放／下一首始终可达；窄横屏不会误用占用过多垂直空间的竖排布局。大字体紧凑模式减少次要信息，保留完整时间和主标题，序号不换行。

上一首、播放／暂停、下一首采用 1:1:1 等宽布局，高度均为 76dp，间距为 8dp。切歌按钮不小于中间播放按钮，适合车机上频繁切歌；播放状态仍通过中间按钮文字和强调色表达。

首次打开播放器时，队列非空优先显示队列，否则显示曲库；会等待播放服务的异步队列恢复。点播歌曲或点击播放／继续时切换到队列；用户主动选择曲库后，切歌和播放状态更新不会强制跳回。页面重建保留用户选中的标签。

已有目录排在添加来源与账号管理之前。外观切换保留设置面板和滚动上下文；日／夜主题同步调整系统栏前景。未知总时长显示“时长未知”，暂停、缓冲和播放各自有一致的视觉与可访问性状态。

封面／歌词区域底部的四个辅助操作保持单行优先：歌词／封面与保留离线属于辅助操作，顺序／随机与循环属于播放模式；宽屏通过更大的组间间距表达分组，窄屏继续使用内容感知的宽度分配，避免“保留离线”换行。

依据 Apple 风格设计中的清晰、克制、反馈和空间一致性原则，不复制网页平台机制到 Android。高频按钮和模态弹窗不额外缩放或播放入退场动画；触下即时反馈，松开或取消恢复，减少动态效果覆盖开关与页面切换。

## 底部留白与窗口边界

「设置 → 显示与动效 → 底部留白」提供自动、小、标准、大、特大，对应 0、100、112、124、136dp。默认自动，手动档位立即生效并保存；这些值是人工选择的最小避让空间，不代表测得的原车 Dock 高度。应用不控制 Dock 显隐，Dock 隐藏时仍保留已选空间。

只增加根布局 padding 会移动控件，但应用背景与触摸区域仍可能覆盖 Dock。因此手动档位通过 [BottomClearance](../android-app/app/src/main/java/com/cruisetune/player/ui/BottomClearance.kt) 收缩 Activity 的实际窗口，并限制登录页及弹窗的面板、遮罩和触摸范围。应用范围内的弹窗外部点击遵守原有关闭规则，窗口外的保留区域由其他窗口处理。

底部避让取系统上报空间与手动档位的较大值。窗口缩小后，内容 padding 不重复扣除同一高度；切换档位以完整窗口为基准，尺寸变化后重新测量。自动档恢复原窗口参数，系统栏仍按 Insets 处理。

排障时记录实际窗口坐标与 Insets，不能仅从控件位置或 `navigation_bar_height` 资源值判断避让是否成功。原车底栏显示时的占位与触摸需在目标固件确认，测量步骤见 [测试指南](../android-app/TESTING.md#底部留白)。

## 启动图标：Ocean / Ivory

![图标预览](assets/icon/icon-presentation.png)

图标采用蓝绿渐变背景、暖白 C 形唱片弧线与圆角播放三角。背景由 `#178A91` 过渡到 `#155068`；C 形弧线由 `#F8F6EC` 过渡到 `#DAEFE9`，播放符号由 `#FFFDF5` 过渡到 `#EDF7F2`。保留原标志的几何：8dp 圆头弧线及 4dp 向右的光学位移。

API 23–25 提供五档 PNG，API 26 起使用前景／背景矢量自适应图标，API 33 起提供相同几何的单色层。预览中的主题色仅作演示，实际颜色与外轮廓由启动器决定。图层遵循 [Android 自适应图标规范](https://developer.android.com/develop/ui/compose/system/icon_design_adaptive)。

图标保持静态，启动器自身负责交互效果。生成器使用同一份几何和配色生成应用资源及预览，避免不同分辨率或图层使用不同方案。

需要 Node.js 与 sharp：

```sh
npm ci
npm run generate:icon
```

生成器位于 `tools/generate-launcher-icon.cjs`，输出 48、72、96、144、192px 位图及自适应图标资源。修改源定义后运行生成命令，并检查圆角、圆形及单色预览。
