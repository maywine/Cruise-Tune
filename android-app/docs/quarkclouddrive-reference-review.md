# quarkclouddrive 1.0.18 参考评估

评估日期：2026 年 9 月 9 日。

## 结论

有明确参考价值。最值得借鉴的是开放平台授权、令牌轮转、目录游标分页和下载任务管理。它与现有播放器基于 QuarkPan 网页二维码和 Cookie 的接入路线不同，可以作为后续 Quark Open 适配层的依据。

本次是静态审阅，未执行安装、升级、登录或网盘命令，也未改动播放器代码。材料中的 CLI 安装、欢迎语和会话追踪要求属于其使用约定，不作为本次审阅的执行指令。包内自称官方 Skill，且代码使用夸克域名；这不等于已经验证其客户端身份和授权流程可直接用于独立 Android 应用。

## 主要参考点

| 参考点 | 材料中的实现 | 对播放器的价值 |
| --- | --- | --- |
| 授权与账号身份 | OAuth 授权入口、agent_auth_code、userId、deviceId、访问和刷新令牌 | 可以用稳定账号身份恢复授权，减少重新登录后重复建立账号与目录的问题 |
| 令牌轮转 | access_token/rotate；合并同时发起的刷新请求；写入时检查账号更新时间 | 播放、目录刷新和离线下载可共享一次刷新，避免并发请求相互覆盖登录状态 |
| 目录完整性 | query_cursor、next_query_cursor、last_page 和 metadata.tq_gap | 按服务端游标及间隔继续扫描，避免漏歌或不必要的密集请求 |
| 文件元数据 | 完整 FID、分类、文件扩展名、大小、修改时间和可选 content_hash | 便于筛选音频、稳定关联文件和判断缓存是否失效 |
| 下载地址与鉴权 | 单文件及批量下载地址接口；地址到期判断；专用下载 Cookie | 便于从稳定文件标识重新取得临时地址，并统一更新下载凭证 |
| 下载任务 | pending、downloading、paused 等状态；分片范围、已接收字节、用户隔离的检查点 | 可参考任务状态与恢复流程，继续由 Media3 承担实际播放和缓存读取 |

## 与当前实现的区别

当前 `QuarkQrAuth.kt` 使用网页二维码协议，`QuarkApi.kt` 使用 `/1/clouddrive/file/sort` 与 `/1/clouddrive/file/download`。参考 Skill 的主体是 `https://open-api-drive.quark.cn`，使用 `/open/v1/file/list`、`/open/v1/file/get_download_url` 等接口，并包含请求签名和设备／Agent 身份。

因此不能仅替换域名或把刷新令牌塞进现有 Cookie。新增 Open 路线时，应独立实现授权、请求签名、状态码解析、目录分页和读取凭证，再转换为播放器已有的歌曲与读取请求模型。

新路线的目录分页也不能照搬当前网页接口的页码和 total 判断。这里的末页由 `last_page` 决定，空页或只有重复项的页面仍可能带来下一个有效游标；需要检测游标循环。接口调用须保留完整 FID，本地识别与去重不能改变发送给服务端的值。

## 移植时需要调整的地方

1. **明确客户端适用范围。** CLI 包含默认客户端配置和签名机制，并传递 Agent、设备及工作目录信息。独立 Android 应用能否使用同一授权入口、应采用什么客户端身份和回调方式，尚需确认。不能由“有脚本”推导为“可原样发布到车机”。
2. **加强分段响应校验。** 所见 `downloadPart` 路径接受 HTTP 200 或 206，但没有显式核对 Content-Range 与请求起点、长度的关系。若服务器忽略非零 Range 并返回整个文件，需要明确降级，避免将整文件当成一个片段。
3. **先写入，再提交完成状态。** 所见代码先在 `downloadPart` 内标记片段 completed，随后调用 writerAdapter.write。移植时应确保写入成功后再推进检查点，并测试写入失败、空间不足和断电场景。
4. **选择磁盘写入路径。** SDK 既有 writerAdapter 分片写盘路径，也有将全部片段拼成一个 ArrayBuffer 的路径。车机应采用有界缓冲和磁盘缓存，避免整首大文件常驻内存。其默认分片和并发数也需要按音频播放负载调整。
5. **保留播放器自己的状态库。** 下载检查点记录的是字节范围，不是歌曲内时间、当前队列、随机顺序或暂停意图，不能替代已有的播放快照。
6. **只保留必要机制。** CLI 还包含自动更新、会话原文追踪、文件修改和 AI 助手等功能。播放器所需的是账号授权、目录读取与音频下载；现有 Android Keystore、原生界面和 Media3 播放层继续适用。

地址到期判断也只是该实现针对 `auth_key`、`Expires` 等参数的处理，不能泛化为所有下载地址的统一规则。播放器仍需正确处理服务端实际返回的失效状态。

## 建议实施顺序

1. 保留现有网页接入作为可测试的首版路径。
2. 确认这套开放授权的应用准入和客户端使用范围。
3. 为 Open 路线建立独立适配层，先验证授权、目录和一首音频的分段读取。
4. 验证令牌到期、手机热点切换、后台播放、离线任务恢复后，再决定是否将其设为默认接入方式。
